# Parallel Search Plan

## Goal

Add root-level parallel search with threads while keeping the rest of the engine simple, predictable, and easy to debug.

For the first version, parallelism should only happen at the root of the search. Everything below the root should remain single-threaded.

---

## Guiding Rules

- Keep the existing sequential search as the baseline.
- Keep iterative deepening sequential.
- Parallelize only root move evaluation.
- Prefer clarity and safety over aggressive optimization in v1.
- Treat budgeted search as a sequential concern for now.

---

## Phase 1: Lock The Scope

Decide exactly what the first parallel version is and is not.

The first version should:

- support root-only parallelism
- keep recursive alpha-beta single-threaded
- keep the sequential path available at all times
- avoid shared mutable search state between workers

The first version should not try to solve:

- recursive parallel search
- shared cancellation across workers
- shared transposition tables
- thread pools or advanced scheduling

---

## Phase 2: Define The Parallel Work Unit

Choose one root move evaluation as the unit of parallel work.

That means:

- the main thread generates and orders root moves
- each worker evaluates exactly one root move
- each worker operates independently
- the main thread remains responsible for combining results

This keeps the model easy to reason about and makes correctness easier to verify.

---

## Phase 3: Add A Threaded Root Execution Path

Introduce a separate parallel branch at the root search layer.

That branch should:

- start from the already ordered root moves
- run root move evaluations in separate worker threads
- keep the normal sequential branch untouched
- be used only when parallel mode is explicitly enabled

At this stage, the focus is not maximum speed. The focus is getting a simple threaded version working correctly.

---

## Phase 4: Keep Result Selection Deterministic

Parallel execution should not make the engine behave unpredictably.

The merge step should:

- collect all worker results on the main thread
- choose the best move using the same scoring rules as sequential search
- use stable tie-breaking so equal-score positions still choose the same move consistently

Deterministic behavior matters for testing, debugging, and trust in the feature.

---

## Phase 5: Preserve Current Search Semantics

The current sequential search should remain the source of truth.

For v1:

- sequential mode should behave exactly as it does today
- iterative deepening should remain sequential
- if parallel mode is disabled, nothing about the search should change
- if a time limit or node limit is set, the search should fall back to sequential mode

This avoids mixing threading with budget coordination too early.

---

## Phase 6: Validate Correctness First

Before worrying about performance, verify that threaded root search preserves behavior.

Validation should focus on:

- same best move as sequential search
- same score as sequential search
- stable tie-breaking
- safe fallback behavior when budgets are present

The goal here is behavioral parity, not proving that threads exist.

---

## Phase 7: Benchmark The Threaded Version

After correctness is stable, measure whether the threaded version is actually helping.

Benchmark across:

- opening positions
- midgame positions
- endgame positions
- shallow and deeper searches

Compare:

- wall-clock time
- throughput
- result consistency

Expect the biggest gains when there are multiple legal root moves and each subtree is expensive enough to justify thread overhead.

---

## Phase 8: Improve The Design After V1

Once the basic threaded version is correct and measured, decide what is worth improving.

Possible follow-ups:

- limit the number of concurrent workers
- replace simple thread launching with a task system or pool
- add shared cancellation for budgeted parallel search
- revisit whether a shared transposition table is worthwhile

These should come only after the first threaded root-search version is stable and understandable.
